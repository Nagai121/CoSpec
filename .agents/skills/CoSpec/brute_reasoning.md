# Brute Reasoning

Brute Reasoning（BR）は、確立しつつある目的と概念的アーキテクチャを基準に、未解決点を合理的に仮決定し、実装可能な定義を複数の整合した仮実装仕様として一括構成するDiscussion actionである。

`Brute`は無制限な列挙または長文出力を意味しない。一案への早期収束を避けて概念的な解空間を検討し、一般性を満たす実質的に異なる候補だけを残す。

## Baseline

- current Specificationが存在する場合は基準仕様として参照する。
- 現在のDiscussion、人間が確定した目的、成果物、制約、非対象、概念的アーキテクチャを共通基準として固定する。
- 関連する明示的なCheck結果がDiscussionまたは参照したMemoryに存在する場合は統合する。
- 人間の決定、確認済み事実、AIの仮定、未確認の外部事実を区別する。
- Shelfを暗黙参照せず、外部調査を自動実行しない。必要な外部事実を参照できない場合は条件付き仮定または未解決事項として扱う。

## Implicit Check

BR開始時に、明示的な`check`の有無にかかわらず、最新の基準情報へCheck相当の検査を行う。

- 未定義、曖昧、矛盾、仕様不足、暗黙の前提、反例、境界条件、失敗可能性を調べる。
- 入出力、状態、責務、処理境界、並行性、永続化、再試行、停止条件、外部依存、環境、再現性、secretsを必要範囲で調べる。
- 過去のCheck結果をそのまま採用せず、その後のDiscussionによる解決、変更、新しい矛盾を反映する。
- 検査結果を独立した長大な一覧として機械的に出力する必要はない。発見事項を仮決定へ接続し、最終的な対応関係を示す。
- 人間が確定した目的または基準アーキテクチャが不足し、AIが目的そのものを創作しなければ候補を構成できない場合は、仮仕様を捏造せず`blocker`を示す。

## Provisional decisions

- 未解決点を独立した回答の集合ではなく、パターン内部で相互に整合する仮決定として扱う。
- 設計判断が不足している場合は合理的な仮決定を置き、人間の好みに依存する判断はパターン間の差分にできる。
- 未確認の外部事実を捏造しない。必要に応じて条件付き仮定を置き、その条件を明示する。
- security、破壊的操作、承認境界、secret保護を仮定によって解除しない。
- 人間の確定事項を仮決定で上書きしない。確定事項同士が矛盾する場合は隠さず示す。
- 暗黙Checkで扱った各重要事項を、`仮決定`、`条件付き仮決定`、`非該当`、`外部事実待ち`のいずれかへ対応させ、黙って省略しない。

## Pattern construction

- 原則として3パターンを作る。実質的に異なる有効な候補が3つ成立しない場合は水増しせず、2案以下とする理由を示す。
- 各パターンに、対象から導かれる一貫した設計原則を持たせる。固定された一般論のテンプレートを機械的に割り当てない。
- 責務分離、状態管理、処理フロー、協調方式、障害境界、依存関係その他の本質的な設計判断に差がない候補を別パターンとして数えない。
- 未解決点ごとの選択肢を無作為に組み合わせず、パターン全体で仮決定、interface、状態、処理、失敗時動作、検証条件を整合させる。
- 人間が明示しない限り4案を超えて作らない。

## General-to-minimal selection

各パターンは、一般性を先に評価し、その後に最小性を評価する。

1. 人間が示した目的、成果物、対象範囲、制約を一般的に満たすか判定する。
2. サンプル、既知テスト、局所条件だけを攻略する候補を除外する。
3. 一般性を満たす候補から、その設計原則と目的達成に不要な機能、論点、抽象化、依存関係、将来想定を除く。
4. 最小性を理由に人間の目的、確定した成果物、比較に必要な本質的選択肢を縮小しない。

## Subagent deliberation

- サブエージェントが利用可能で、対象が独立した複数案の検討に値する場合は、独立提案者および相互批評者として使用できる。
- 主エージェントは、人間の確定事項、基準アーキテクチャ、未解決点、制約、非対象だけを含む共通の問題定義を作る。secretsまたは無関係なMemoryを渡さない。
- 初稿では各提案者へ他案を見せず、異なる設計原則から独立した仮実装仕様を作らせる。必要な場合は初稿後に他案への反論、欠落指摘、修正を行わせる。
- サブエージェントにはDiscussionだけを許可し、ファイル変更、実装、外部操作、Specification更新を行わせない。
- サブエージェントの出力を人間の決定として扱わない。主エージェントが重複、矛盾、一般性、最小性、未解決点の網羅を検査して最終出力を構成する。
- サブエージェントが利用できない場合は、単一エージェントが候補間の独立性を保ちながら同じ工程を順次行う。利用不能だけを理由にBRを停止しない。

## Output contract

出力は対象に必要な範囲へ調整し、次の情報を比較可能にする。

- 共通基準: 確定事項、固定する概念的アーキテクチャ、対象となる未解決点、共通制約。
- 各パターン: 設計原則、仮決定、概念的アーキテクチャ、責務、interface、状態と処理フロー、失敗時動作、実装境界、検証条件、利点、欠点、主要リスク。
- 対応関係: 暗黙Checkの重要事項を各パターンがどのように扱ったか。
- 比較: 本質的な差分、共通して必要な部分、選択基準、残存する未解決事項。
- 推奨: 根拠がある場合だけ推奨案を示し、判断できない場合は選択に必要な人間の決定を示す。

内部検討を逐語的に開示せず、仮決定とその必要十分な根拠を示す。対象に不要な定型項目は省略できるが、重要な未解決点への対応を省略しない。

## Approval boundary

- BR自体は成果物、Specification、archive、Logを変更せず、実装または外部操作を行わない。保存対象が生じた場合のMemo post-actionは別actionとして扱う。
- BRの仮決定と各パターンはAIの提案であり、人間のacceptedまたはhuman-confirmedとして扱わない。
- BR直後の単独`exe`を、いずれかのパターン選択または全仮決定の承認として扱わない。
- 人間が対象パターンと修正内容を明示した場合だけ、今回限りのDiscussion差分としてExeの承認対象にできる。
- 永続化する場合は、人間が選択または修正した内容だけを`update`でSpecificationへ反映する。
